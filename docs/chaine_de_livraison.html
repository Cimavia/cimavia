Schéma global

Cinq zones. Les flèches pleines produisent quelque chose (image, tag, branche) ; les pointillées vérifient ou lisent sans rien produire.

Poste de dev GitHub : dépôt + Actions GHCR : registre d'images NAS Synology (preview) Services tiers

Le schéma est large : faites-le défiler horizontalement sur un petit écran.

Parcours d'un changement

Du commit à l'écran du Coach bêta. Chaque étape a une barrière, et c'est elle qui l'empêche d'avancer.

Poste

Commit

lint-staged passe biome check --write sur les fichiers indexés, puis commitlint relit le message.

Conventional Commits, sujet en minuscule, types feat fix chore docs refactor test perf ci revert.

GitHub

PR vers main

ci.yml : qualité et e2e en parallèle, puis SonarCloud une fois la couverture e2e récupérée.

3 checks requis : Lint + Typecheck + Test · E2E · SonarCloud (couverture > 80 %, duplication < 3 %).

GitHub

Merge sur main

La CI se relance sur main. En parallèle, api-image.yml pousse cimavia-api:sha-… et release.yml met à jour la PR de release.

Aucune : une image est publiée même si un test est rouge. Le blocage intervient à la promotion.

GitHub

Release

Merger la PR de release incrémente package.json, CHANGELOG.md et app.json, pose le tag vX.Y.Z, et ce commit produit cimavia-api:X.Y.Z.

Changement de version détecté en comparant package.json à celui de HEAD~1.

Actions → GHCR

Promotion

Lancée à la main avec X.Y.Z. Construit le web au tag avec l'URL de l'API figée, puis retague les deux images en :preview par digest et avance la branche preview.

Tag sur main, version plus récente que preview, 3 checks verts sur ce commit, image API présente.

NAS

Tirage

pull-preview.sh voit un nouveau digest, télécharge le compose de ce commit, lance up -d ; l'API exécute prisma migrate deploy au démarrage.

API healthy en moins de 300 s côté NAS, et le job confirm attend jusqu'à 20 min.

Workflows GitHub Actions

Six workflows et un Dependabot. Toutes les actions sont épinglées par SHA et chaque job déclare ses propres permissions (permissions: {} par défaut).

ci.yml · CI› La porte de qualité : ses trois jobs sont les checks requis sur main et ceux que la promotion revérifie. push mainpull_request → mainannule le run précédent de la même ref

Lint + Typecheck + Test

quality · parallèle
  1. pnpm install --frozen-lockfile --ignore-scripts
  2. prisma generate (DATABASE_URL fictive)
  3. pnpm biome ci .
  4. pnpm turbo typecheck
  5. pnpm turbo test
  6. pnpm check:i18n (sans --strict)

E2E (isolation multi-tenant)

e2e · parallèle
  1. copie .env.test.example → .env.test
  2. docker-compose.test.yml up -d --wait (PG 5434)
  3. docker-compose.yml run --rm silo-setup
  4. pnpm turbo test:e2e --filter=@cmv/api
  5. upload coverage-e2e/lcov.info (1 jour)
  6. logs des services si échec

SonarCloud Analysis

needs: e2e
  1. pnpm turbo test (lcov shared, api, web, mobile)
  2. download de l'artefact coverage-e2e
  3. scan avec qualitygate.wait=true, timeout 300 s
  4. projectVersion = version de package.json
release.yml · Release› release-please ouvre ou met à jour la PR de release ; la merger crée le tag vX.Y.Z et la release GitHub. push mainworkflow_dispatch→ PR de release · tag
Jeton
GitHub App (RELEASE_APP_*), pour que la PR de release déclenche la CI, ce que GITHUB_TOKEN ne permet pas.
Fichiers bumpés
package.json, CHANGELOG.md, apps/mobile/app.json ($.expo.version), manifest.
Changelog
feat → Fonctionnalités · fix → Corrections · perf · revert · refactor/ci/chore → Technique · docs et test masqués.
Tag
vX.Y.Z sans composant (include-component-in-tag: false).
api-image.yml · Images — API (GHCR)› Construit et publie l'image de l'API, sans déployer. Le renommage du fichier est prévu dans #271. push main · apps/ packages/ lockfile package.json CHANGELOG→ cimavia-api:sha-… (+ :X.Y.Z)
Tags
sha-xxxxxxx à chaque commit ; X.Y.Z en plus quand package.json change de version par rapport à HEAD~1.
Build
apps/api/Dockerfile : turbo prune @cmv/api → build shared + api → pnpm deploy --prod → runtime avec prisma generate. Plateforme linux/amd64, cache GHA.
Build args
APP_VERSION, APP_BUILD (SHA court).
Au démarrage
docker-entrypoint.sh : prisma migrate deploy puis node dist/main.
Sans concurrency
Volontaire : annuler un build en cours pouvait perdre l'image X.Y.Z, la seule que la promotion sait retaguer.
promote-preview.yml · Promotion — preview› Le seul chemin vers le Coach bêta : vérifie la version, construit le web, retague les images et attend que le NAS redémarre. workflow_dispatch · version X.Y.Zune promotion à la fois→ :preview · branche preview

Vérifier la version

verify
  • format X.Y.Z ; le tag vX.Y.Z existe et est sur main
  • fait avancer preview (plus récente, et preview est un ancêtre)
  • les 3 checks requis sont success sur ce SHA
  • cimavia-api:X.Y.Z présente sur GHCR
  • PREVIEW_PUBLIC_API_URL renseignée

Construire le web

needs: verify
  • checkout du SHA du tag
  • cohérence Sentry (token ⇒ org + projet)
  • build apps/web/Dockerfile (nginx) avec VITE_API_URL, VITE_APP_ENV=preview, DSN, release Sentry X.Y.Z+sha
  • push cimavia-web:preview-X.Y.Z

Publier sur preview

needs: verify, build-web
  • cimavia-api:preview ← digest de :X.Y.Z, avec contrôle d'égalité
  • cimavia-web:preview ← digest construit
  • push du SHA vers la branche preview (jeton App)

Attendre le NAS

needs: verify, publish · 25 min max
  • interroge /health toutes les 20 s
  • succès si uptime est inférieur au temps écoulé depuis la promotion (l'API a redémarré) et si /health/ready répond
  • rouge après 20 min, avec les endroits à regarder sur le NAS
mirror-images.yml · Images tierces — miroir GHCR› Copie SILO et son client mc de Docker Hub vers ghcr.io/cimavia, et signale les versions épinglées en retard. lundi 06:00 UTCworkflow_dispatch · tag optionnelpush main sur ce fichier
Copie
Dernière version RELEASE.… de pgsty/silo et pgsty/mc, plus le tag demandé et les tags épinglés dans les deux composes ; les images déjà présentes sont sautées.
Surveillance
Si un compose (apps/api ou deploy/preview) épingle une version plus ancienne, ouvre ou réécrit l'issue [silo-version] (area: infra, prio: high).
reminder-tick.yml · Rappels — tick› Tient lieu de cron métier : déclenche l'envoi des rappels dus sur l'API de preview. toutes les heures, à :00workflow_dispatch
Appel
POST {PREVIEW_PUBLIC_API_URL}/internal/reminders/tick avec l'en-tête x-cimavia-tick-secret, 60 s max.
Préalables
Échoue explicitement si la variable ou le secret manque, plutôt que de laisser l'API répondre 401.
dependabot.yml› Maintient les SHA épinglés des actions à jour : une PR groupée par semaine, préfixe ci, label type: chore. hebdomadaire→ PR
Périmètre
github-actions uniquement ; les dépendances npm ne sont pas suivies par Dependabot.

Points à noter

Ce que le schéma ne dit pas tout seul : des choix assumés, et des points à surveiller.

choix

Le NAS tire, GitHub ne pousse pas. Aucun workflow n'a d'accès au NAS : il suffit de poser le tag :preview, et le job confirm observe le résultat de l'extérieur par /health.

choix

Publier n'est pas livrer. api-image.yml publie même quand un test est rouge ; c'est la promotion qui exige les 3 checks verts sur le commit taggé.

choix

Le web est construit une fois par tier, au moment de la promotion et depuis le tag, parce que l'URL de l'API est figée dans le bundle. L'API, elle, est construite une seule fois et retaguée par digest.

choix

Le compose voyage avec la version. pull-preview.sh lit le commit dans le label org.opencontainers.image.revision de l'image et télécharge deploy/preview/docker-compose.yml à ce commit, ou deploy/dev/… pour les versions antérieures au déplacement. Il détecte aussi un renommage de projet compose et arrête l'ancien.

à voir

Les tests unitaires tournent deux fois par run : dans quality et dans sonarcloud, qui a besoin des lcov. Un artefact de couverture depuis quality, comme pour les e2e, éviterait le doublon.

à voir

La production n'a pas de chaîne. deploy/prod/ ne contient qu'une règle de cycle de vie de bucket, en attendant la décision HDS (#259). Côté mobile, le profil EAS production existe mais aucun script ne l'appelle, et tous les builds EAS sont manuels.

à voir

Dependabot ne suit que les actions. Les versions npm sont épinglées à la main (cf. CLAUDE.md), sans rappel automatique.

à voir

Le nom api-image.yml ne décrit plus son rôle : son renommage relève de #271, la branche en cours.
